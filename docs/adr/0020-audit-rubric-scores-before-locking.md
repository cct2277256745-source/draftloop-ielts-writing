# Audit Rubric scores with calibration evidence before locking

The operator's 2026-09-12 specification supersedes the post-lock-only timing in ADRs 0011 and 0019 for the local browser assessment flow: complete Rubric-only scoring first, independently audit against gated retrieval evidence, compare the two code-derived overall scores, then lock either the initial assessment or a new Rubric-based re-score. Trigger re-score when `abs(initial - audit) >= 0.5` for an initial score `>= 7.0`, and only `> 0.5` below 7.0; criterion differences explain disagreement but do not introduce extra triggers.

The audit never receives the initial bands, target band or learner history, preventing anchoring; its cited reference judgement is compared by code. A triggered re-score receives the Official Rubric, validated current Student Evidence, initial findings, valid calibration evidence from a fresh disagreement-focused retrieval, and the disagreements, and must pass the existing criterion validators; averaging, choosing the favourable score, or copying the audit is not a finalization policy. Calibration evidence retains no direct score authority, and existing package rights and provenance gates remain intact; an unavailable audit is recorded explicitly, never represented as an agreement.

The frozen package has no TA objects. A separately versioned, hash-pinned Task 1 commentary sidecar provides attributed original summaries for all four Task 1 criteria; it contains no copied scripts or inferred criterion bands. Task-specific routing prevents TR relabelling and cross-task substitution. The sidecar uses lexical retrieval, has explicitly limited coverage, and runs through the same authority/provenance/rights gate. It does not mutate the frozen package or expand the existing private authorization scope.
